### Objectives

Introduce the problem, architecture, processing workflow, and deployment results of **CloudManga**, a manga reading and review web application built using **Serverless** architecture on **Amazon Web Services**.

## 1. Problem and Solution

**CloudManga** was developed to create a web application that allows users to search for manga, view detailed information, read chapters as images, and submit reviews after logging in.

To reduce backend server management, the system adopts **Serverless** architecture. The frontend is built using **HTML, CSS, and JavaScript** and deployed on **GitHub Pages**. Backend functions are handled through **Amazon API Gateway and AWS Lambda**.

**Amazon Cognito** handles user authentication, while **Amazon DynamoDB** stores review data.

## 2. Architecture and Storage

The **CloudManga** system uses the following main components:

- **GitHub Pages:** Deploys the web frontend and serves users over HTTPS.
- **Amazon API Gateway:** Provides APIs for communication between the frontend and backend.
- **AWS Lambda:** Processes requests to retrieve manga lists, read chapters, and manage reviews.
- **Amazon S3:** Stores the `manga.json` file, cover images, and JPG pages; the Bucket is configured as private.
- **Amazon Cognito:** Manages user accounts, login, and authentication tokens.
- **Amazon DynamoDB:** Stores user ratings and reviews.
- **AWS IAM:** Grants Lambda permission to access AWS resources.
- **Amazon CloudWatch:** Records logs and supports monitoring Lambda function activities.

Image files in S3 are accessed through **Presigned URLs** generated by Lambda, reducing the need to make the Bucket publicly accessible.

## 3. Processing Workflow

1. Users access the **CloudManga** frontend on **GitHub Pages**.
2. The frontend sends a `GET /manga` request to **API Gateway** to retrieve the manga list.
3. **Lambda** reads data from **S3** and returns manga information along with Presigned URLs for cover images.
4. When a user selects a chapter, the `GET /chapter` API invokes Lambda to retrieve the corresponding list of JPG images from S3.
5. When logging in, users are redirected to **Amazon Cognito** for authentication and token issuance.
6. When submitting a review, **API Gateway** validates the **JWT** before **Lambda** stores the data in **DynamoDB**.
7. The frontend calls `GET /reviews` to retrieve and display reviews and ratings.

## 4. Deployment Scope

The Workshop focuses on building a small-scale manga reading application with six manga titles, using **AWS Serverless** services.

The implemented features include manga listing, searching, detail pages, JPG image reading, Cognito login, and DynamoDB-based reviews. The frontend is deployed on GitHub Pages. The backend consists of three main Lambda functions: `CloudManga-GetManga`, `CloudManga-GetChapter`, and `CloudManga-Reviews`.

During the AWS learning process, services such as EC2, VPC, Docker, ECS, and Application Load Balancer were also practiced in separate labs. However, they are not the main processing components of the current CloudManga Serverless version.

## 5. Results

CloudManga has been deployed on GitHub Pages and connected to AWS services. Testing confirmed the ability to display a list of six manga titles, retrieve cover images from S3, read chapters using JPG images, log in through Cognito, and submit reviews stored in DynamoDB.

The project helped me better understand how to connect AWS services, manage IAM permissions, build APIs, and deploy a web application based on Serverless architecture.
